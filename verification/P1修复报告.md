# P1 修复报告

日期：2026-11-22
方式：TDD（失败测试复现 → 修复 → 回归验证）

## P1-1　H-1：全局吞异常
**问题**：`index.js` 的 `uncaughtException`/`unhandledRejection` 记录后继续运行，进程处于未定义状态，掩盖缺陷。
**修复**：记录后立即 `process.exit(1)`；新增 `src/supervisor.js` 作为启动包装器，子进程崩溃后指数退避自动重启（1s→5s）；一键启动脚本改走 supervisor，停止时先 kill 子进程避免残留。
**验证**：手动杀掉 18080 监听子进程（PID 21944），3 秒内新 PID 接管、health 正常 → 自动重启成功。停止脚本确认 18080 关闭、无 supervisor 残留、其它服务（8080/18787）未受影响。

## P1-2　H-2：流管道无 error 监听
**问题**：`createReadStream().pipe(res)` 无 error 监听，TOCTOU 窗口下请求永久挂起 + fd 泄漏。
**修复**：新增 `src/stream-utils.js:pipeWithErrorHandling()`，统一处理流 error（未发头→404，已发头→destroy）与 `res.on('close')` 销毁上游流；api.js 三处（Range 流、完整流、下载流、ccMixter 代理）全部改用；顺带统一了 ccmixter 重复的 error 监听。
**验证**：`test-reliability.mjs` 用故意 destroy 的 Readable 验证请求 2s 内结束（不挂死），通过。

## P1-3　H-3：曲库扫描无事务/并发
**问题**：先 `DELETE` 全部再逐条 upsert、无事务、stat 未捕获 → 文件变动时可清空库；watcher 与 `POST /api/scan` 可并发。
**修复**：`library.js` 改为"先收集（含 stat try/catch）→ 事务内 upsert + 删除多余记录"，失败 ROLLBACK；模块级 `scanningPromise` 去重，并发调用复用同一 Promise。
**验证**：`test-reliability.mjs` 验证并发调用返回同一 Promise、重复扫描正常完成，通过；真实服务器 health/音源/曲目数正常。

## P1-4　H2（前端）：订阅未取消 + 并发切歌竞态
**问题**：`playerStateStream.listen` 订阅未保存/未取消；自动/手动切歌并发多个 `setUrl`/`play()`，last-write-wins 但每个分支都 play，可能跳曲。
**修复**：保存 `_stateSub`，dispose 先 cancel 再 dispose player/playback；新增 `lib/play_token.dart` 代次令牌，`_play` 领取 token，`await setUrl` 后若 token 已变则放弃本分支（不 play、不 push、不报错）；所有异步分支加 mounted 判断。
**验证**：`play_token_test.dart` 2 个用例通过；flutter analyze 无 error，flutter test 15/15 通过。
