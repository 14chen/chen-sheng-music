# P0 修复报告

日期：2026-11-22
方式：TDD（先写失败测试复现 → 修复 → 回归验证）

## P0-1：认证绕过（C-1）

**问题**：`auth.js` 信任客户端可控的 `X-Forwarded-For`/`cf-connecting-ip` 头判定"局域网"，配合默认局域网免口令，加一个伪造头即可绕过口令。

**修复**（`server/src/auth.js`）：
- 彻底移除对 XFF/CF 头的信任；设了 ACCESS_KEY 即对所有 API 校验口令。
- 仅 `/` 和 `/api/health` 放行（状态探测需要）。
- 移除 query 口令（防 URL/日志泄露），仅**例外**：`/api/tracks/*/stream` 允许 `?key=`——因为 just_audio 底层请求无法设置自定义 HTTP 头（实测不改会 401 导致播放失败，这是修复中发现并处理的回归）。
- 前端 `streamUrl` / ccMixter 代理 URL 拼接口令。
- 局域网现在也必须填口令（App 设置里已有），状态脚本改为从 `.env` 读口令带 header。

**验证**：
- `node --test test-auth.mjs`：7/7 通过（伪造头/无口令/query 均 401，正确口令 200，流端点带 key 放行）。
- 真实服务器实测：伪造XFF/伪造CF头/无口令/query口令 → 401；正确口令 → 200；流媒体带 key → 206 音频、无 key → 401。
- 状态脚本仍正常读取音源/曲目数。

## P0-2：切歌后播放页显示旧歌（H1）

**问题**：PlayerPage 由 `Navigator.push` 的 builder 闭包捕获旧 `t`，父级 setState 不重建已入栈路由，`didUpdateWidget` 永不命中，`onChanged` 是死代码。切歌后音频变了但界面显示旧歌，且下载/歌词作用于错误歌曲。

**修复**：
- 新增 `lib/track.dart`（纯数据模型）、`lib/playback_state.dart`（`PlaybackState`：`ValueNotifier<Track?>` + `ValueNotifier<PlayMode>` 唯一状态源）。
- HomePage 持有 `PlaybackState`，切歌/切模式时更新它（切模式改为**同步**更新状态+控制器，再异步持久化，修掉 H3 竞态）。
- PlayerPage 接收 `playback`，`initState` 监听两个 notifier、`dispose` 取消监听，收到通知即 `setState` 刷新 → 标题/封面/下载/歌词目标全部跟随当前曲目。
- 删除失效的 `onChanged`/`didUpdateWidget` 分支。

**验证**：
- `flutter test`：13/13 通过（新增 3 个 PlaybackState 广播测试）。
- `flutter analyze`：无 error。
- Playwright 无头截图（capture-h1.mjs）：切歌前显示「02的爱恋」→ 点下一首后显示「小雪 - 红笔」，无 console 错误。见 `screenshots/p0-before-next.png` / `p0-after-next.png`。

## 行为变化（需知晓）

- 局域网访问现在**必须**填访问口令（此前免口令）。App 设置里填一次即可，公网口令与局域网相同。
