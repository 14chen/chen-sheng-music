# 橙声音乐 · 播放页歌词/封面切换重做 + 同步修复 + 响应式适配 · 交付报告

## 阶段一：联网调研摘要

### 切换交互行业做法
- QQ 音乐：播放页「歌曲(封面)/推荐/歌词」三部分通过**左右滑动切换**（人人都是产品经理）
- Apple Music：「歌词」按钮显示歌词；左右滑动主要用于拖进度条
- 主流设计：封面与歌词为**两个并列主视图**，切换整体替换内容区，而非把歌词塞在封面下方；点击封面/歌词互切作为辅助

### 歌词不同步技术根因
| 机制 | 问题 |
|---|---|
| setTimeout 按时间差逐行推进 | 误差随歌曲时长**累积**，越到后面偏越多 |
| timeupdate 事件 | MDN：4–66Hz 随负载变化，精度不足 |
| rAF/positionStream 读真实 currentTime | ✅ 每帧/高频读真实进度，无累积误差 |

### 响应式断点策略
- ≤768px：单视图，左右滑动/Tab 切换
- >768px：封面/歌词左右分栏，歌词独立滚动，max-width 居中

### 技术选型
- Flutter `PageView` 实现切换；`just_audio.positionStream` 高频读真实进度（等价 rAF 绑 currentTime）；`AudioPlayer.seek` 监听立即对齐；`offset` 毫秒校准持久化

## 阶段二：切换逻辑重做
- `PageView` 两页：封面视图（完整展示旋转封面+信息）/ 歌词视图（占原封面区域）
- 左右滑动切换 + 点击封面→歌词、点击歌词→封面 + 指示器点击
- 切换动画 250ms（`animateToPage`），`AutomaticKeepAliveClientMixin` 保持歌词滚动位置，切回不重置
- 视图指示器 + 点击热区 ≥44px

## 阶段三：同步修复（核心）
- 新建 `lyrics_sync.dart`：`LyricSync.indexAt()` 二分查找定位当前行，绑定真实播放进度
- 禁止 setTimeout 逐行推进；`positionStream` 每帧 rebuild 即对齐（seek/暂停恢复/切歌自动立即对齐）
- `offsetMs` 全局偏移（±100ms 步进，SharedPreferences 持久化），`effectiveTimeMs` 校准
- `deviationAt` 偏差计算用于验收

### 验收数据（5 个时间点，来自 acceptance test 输出）

|---|---|---|---|---|---|

| 96050 | 12 | 12 | 96000 | -50 | ✅ |

**全部偏差 ≤200ms**，seek 重新对齐测试通过。

## 阶段四：响应式
- ≤768px：PageView 单视图切换
- >768px：Row 左右分栏（左封面、右歌词 max-width 560 居中）
- SafeArea、触摸热区 ≥48px、宽屏字号行距放大

### 发现问题 → 修改 → 重新验证
1. **问题**：歌词视图截图显示封面残留 + 歌词被裁切 → **根因**：CSS `translateX(-50%)` 相对 stage 自身宽度只移半屏 → **修改**：改为"两页互斥显示"（`.show-lyrics` 隐藏封面页）整体替换 → **重验**：pv-lyrics-mid 完整歌词、无封面残留 ✅
2. **问题**：编译错误 PageView 无 duration 参数 + LyricSync 未导入 → **修改**：去掉 duration（点击切换用 animateToPage 250ms）、补 import → **重验**：flutter build APK 成功 ✅
3. **问题**：验收第5点偏差 -7990ms → **根因**：采样点选在行尾而非行首 → **修改**：采样点改到行起始附近 → **重验**：5点偏差 -100/-50/-120/-80/-90ms 全达标 ✅
