# 橙声君 · 五模块修复与优化 交付报告

## 任务一：歌词滑动交互重构（核心）
**旧机制已彻底移除**：删除了「回到当前歌词」悬浮按钮及相关状态（`_showBackToCurrent`、`_backToCurrent`）。

**新机制**：
- **5 行可见**：`itemExtent=84`、`viewport=420`，当前行严格居中，上下各 2 行；按距离渐隐（1.0 / 0.66 / 0.34）与缩放（1.0 / 0.94 / 0.88）。
- **滑动预览不打断播放**：`onVerticalDrag*` 跟手滚动歌词 + 计算预览时间，**不调用 player.seek / pause**；父级 `_controls()` 把播放/暂停按钮临时替换为橙色【✓ 确认跳转】按钮，按钮上方实时显示预览时间（如 `1:03`）。
- **松手 1 秒待确认**：单个 `Timer(1000ms)`；期间 UI 保持预览、不回弹，音乐按原进度继续播放（`positionStream` 更新被 `_pendingConfirm` 屏蔽，不会自动居中）。
- **确认跳转**：点击✓按钮 → `LyricsPanelState.confirmSeek()` 取消定时器 → 执行真正 `player.seek()` → 按钮恢复。
- **超时回弹**：1 秒到 → 清除预览、按钮恢复 → 平滑 `animateTo` 回当前真实播放行。
- **防定时器叠加/泄漏**：`_confirmTimer` 单一字段；每次 dragStart / confirm 前先 `cancel()`；`dispose()` 中再次取消并置 null；8px 移动阈值避免点击误触。

## 任务四：移动端音源导入报错修复
**根因**：用户导入的是 MusicFree 格式 `.js` 插件（`module.exports = {...}`），旧前端对其执行 `jsonDecode` → FormatException → 报错。
**修复**：
- 前端按扩展名/内容识别 `.js` 插件，不再 JSON 解析；改用 `withData: true` 读取字节（移动端沙盒兼容），通过 `Api.importSourceFile()` 以 `application/octet-stream` 上传原始字节。
- 后端新增 `POST /api/sources/custom/file`（`express.raw`，5MB 限制），保存到 `custom-plugins/`，解析 `platform` 元数据命名，注册音源并**立即出现在切换列表**。
- 错误提示具体化：`_explainImportError()` 分类处理超时/网络/401/403/413/400/格式错误/文件读取失败；`debugPrint` 打印完整错误与堆栈。
- CORS 放行局域网 IP 与 `capacitor://localhost` 等移动端来源（API 仍强制 `X-Access-Key`）。
- 插件依赖缺失时给出明确提示（"请在服务器执行 npm i axios cheerio crypto-js dayjs he 后重启"），不再崩溃或静默失败。
- **实测**：用用户提供的 `哔哩哔哩.js` 导入成功，toast 显示清晰提示，音源列表立即出现新项。
