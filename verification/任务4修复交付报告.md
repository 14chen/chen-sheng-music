# 橙声君 · 四项具体问题修复交付报告

## 任务一：歌词缺失与校准

### 《1.02的爱恋》（02的爱恋）
- **根因1**：服务器缓存里存在一条被错误标记为 `synced=true` 的"自定义歌词"，但内容没有 `[mm:ss.xx]` 时间轴 → 解析出 0 行，直接把正常歌词全遮住了。已删除该覆盖。
- **根因2**：原 LRC 是中日混杂单行文本，外文行没有中文译文，不满足"原文 + 中文翻译"双行结构。
- **修复**：
  - `lyrics.js` 容错：自定义歌词声明 synced 却无时间轴时不再返回空歌词，回退到本地/在线源
  - `saveCustomLyrics()` 保存校验：检测不到时间轴自动降级为纯文本
  - 新增双语 LRC 格式 `[时间]原文 | 中文翻译`，解析器/结构化模块/翻译模块全链路支持（自带译文不被机器翻译覆盖）
  - 重写《多多poi - 02的爱恋.lrc》：保留全部 90 行原始时间戳，为 46 个日文/英文行补上中文译文，时间轴完全对齐
- **实测**：90 词条，46 行已译，0 空译，0 截断 ✅

### 《红笔》
- **根因**：LRC 文件只有 17 行、到 00:58.71 就结束，而音频长 3:06 —— 源文件本身被截断（非解析错误）。
- **修复**：安装 Python 3.11 + faster-whisper，用已缓存的 small 模型对完整音频重新转录；采用**词级时间戳**按语义分行，得到 62 行、末行 169.70s 的完整歌词（`server/scripts/transcribe-full.py`）。
- **实测**：62 词条，覆盖到 2:49，无时间轴断裂 ✅
- 说明：medium 模型缓存不完整且网络不可达，使用 small；识别文本为 AI 转录（粤语歌有少量识别误差），时间轴精准。

## 任务二：自定义音源导入
- **系统文件选择器**：新增 `file_picker` 依赖；设置页增加"从文件导入音源（系统文件选择器）"按钮，支持 JSON/JS/TXT（JS 自动提取 `module.exports`/`export default` 中的 JSON 对象）
- **服务端即时注册**：`POST /api/sources/custom` + `custom-sources.js`（配置持久化、重启自动恢复；支持 API 地址与插件路径两种模式，插件路径限制在 custom-plugins 目录防越界）
- **UI 状态同步**：导入成功后服务端返回最新音源列表，`setState` 立即刷新"音源切换"下拉，无需重启；为避免不可用源报错，导入后只加入列表、不强制切换
- **实测**：真实 App 内通过文件选择器导入 `sample-source.json` → 下拉列表立即出现 `mycloud` ✅
